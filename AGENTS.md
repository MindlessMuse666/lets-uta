# AGENTS.md — инструкция для агента (нейросети)

**Версия: v2** (2026-08-15)

Ты работаешь над проектом медиаплеера с караоке. Твой источник истины — `TECH.md` (версия v2) в корне репозитория. Прочитай его полностью перед началом любой задачи.

## Обязанности

- Реализовывать слайсы строго по порядку, один слайс за сессию.
- Использовать только те технологии, типы, функции и UI-компоненты, которые описаны в `TECH.md`.
- Не выдумывать контракты. Схема базы данных v2 расширена полями `meaning` (TEXT, nullable), `composers` (TEXT JSON-массив) и `artists` (TEXT JSON-массив). Никаких сторонних полей, таблиц или сущностей добавлять нельзя.
- При нехватке контракта — выдавать блок `CONTRACT GAP` (как в `TECH.md`) и останавливаться.
- Писать тесты из критериев приёмки, а не из реализации.
- Использовать эталонный `songs_dataset.json` для наполнения базы (`scripts/seed.ts`) и сквозных тестов.
- Следовать конвенциям кода, коммитов и комментариев.

## Инструменты (Skills и MCP)

Ты можешь использовать следующие skills и MCP-серверы для помощи в разработке:

### Skills (из репозитория `multica-ai/andrej-karpathy-skills` и Anthropic)

1. **`frontend-design`** – для создания эстетичных интерфейсов в стиле Vocaloid (цвета #00E5FF и #FF4081, бейджи вокалоидов, плавные анимации, типографика).
2. **`performance-optimization`** – для оптимизации загрузки, рендеринга, работы с медиа (кэширование, ленивая загрузка, эффективные хуки).
3. **`andrej-karpathy-skills`** – общий набор навыков для ИИ-ассистенции (может помочь с логикой синхронизации, разбиением текста и т.п.).

### MCP-серверы

1. **`filesystem`** – для чтения/записи файлов пользователя (загружаемые медиа, работа с файловой системой проекта, парсинг `songs_dataset.json`).
2. **`sqlite`** – для прямого доступа к БД (проверка схемы v2, выполнение запросов, проверка JSON-функций SQLite для фильтрации по `artists`).
3. **`web-search`** – для поиска информации о вокалоид-песнях, текстах, если потребуется (но в основном данные берутся из `songs_dataset.json` или вводятся пользователем).

Используй их по необходимости, но помни, что основная логика должна быть реализована в коде, а не полагаться на внешние запросы.

## Порядок работы над слайсом

1. Прочитай описание слайса в `TECH.md`, раздел 14.
2. Составь план: какие файлы нужно создать/изменить, какие тесты написать.
3. Реализуй код, следуя структуре и контрактам.
4. Напиши тесты, проверяющие критерии приёмки.
5. Запусти `npm run gate` и убедись, что всё зелено.
6. Сделай коммит(ы) по конвенции.
7. Проверь Definition of Done (раздел 12).

## Коммиты

- Используй Conventional Commits: `type(scope): <краткое описание>`, `fix(scope): <краткое описание>`, `test(scope): <краткое описание>`, `refactor(scope): <краткое описание>`, `chore(scope): <краткое описание>`.
- Коммить по ходу работы, небольшими логическими шагами.
- Все сообщения на русском языке строчная буква, без точки.
- Длина заголовка коммита не должна превышать 72 символов.

## Примеры

- `feat(upload): добавлена форма загрузки файла с метаданными и валидацией`
- `feat(db): добавлена поддержка meaning, composers и artists в схему v2`
- `test(sync): добавлен тест на идемпотентность для эндпоинта синхронизации`
- `test(filter): добавлены тесты фильтрации по вокалоидам и языкам`
- `fix(ui): корректная подсветка при событии timeupdate`
- `docs(readme): добавлено демо главной активности`

## Если что-то неясно

Обратись к `TECH.md`, раздел CONTRACT GAP. Если проблема не решается – остановись и запроси уточнение у пользователя.
