# AGENTS.md — инструкция для агента (нейросети)

**Версия: v3** (2026-08-15)

Ты работаешь над проектом медиаплеера с караоке. Твой источник истины — `TECH.md` (версия v3) в корне репозитория. Прочитай его полностью перед началом любой задачи.

## Обязанности

- Реализовывать слайсы строго по порядку, один слайс за сессию.
- Использовать только те технологии, типы, функции и UI-компоненты, которые описаны в `TECH.md`.
- Не выдумывать контракты. Схема базы данных расширена полями `meaning` (TEXT, nullable), `composers` (TEXT JSON-массив) и `artists` (TEXT JSON-массив). Никаких сторонних полей, таблиц или сущностей добавлять нельзя.
- При нехватке контракта — выдавать блок `CONTRACT GAP` (как в `TECH.md`) и останавливаться.
- Писать тесты из критериев приёмки, а не из реализации.
- Использовать эталонный `songs_dataset.json` для наполнения базы (`scripts/seed.ts`) и сквозных тестов.
- Следовать конвенциям кода, коммитов и комментариев.

## Инструменты (Skills и Инструменты)

### Skills

1. **`vocaloid-svelte5-craft`** (`.opencode/skills/vocaloid-svelte5-craft.md`):
   - Строгий синтаксис Svelte 5 Runes (`$state`, `$derived`, `$effect`, `$props`, snippets). Запрет на использование устаревшего синтаксиса Svelte 3/4.
   - Гайдлайн по UI/дизайну в стилистике Vocaloid Cyberpunk (акценты `#00E5FF`, `#FF4081`, `#FFD543`, контрастность строк караоке).
   - Правила соблюдения контрактов и архитектурных границ `src/lib/server/` vs `src/lib/ui/`.

### Нативные инструменты окружения (Native Tools)

Внешние MCP-серверы не используются. Вся разработка и верификация происходят через встроенные инструменты OpenCode:

1. **File Ops** (`read_file`, `write_file`, `list_directory`, `grep`) — работа с кодом, шаблонами и фикстурами.
2. **Terminal / Bash** — запуск проверок и тестов:
   - `npm run gate` — полный запуск проверок (линтер, типы, юнит- и e2e-тесты).
   - `npm run seed` — наполнение тестовой БД.

## Порядок работы над слайсом

1. Прочитай описание слайса в `TECH.md`, раздел 14.
2. Составь план: какие файлы нужно создать/изменить, какие тесты написать.
3. Реализуй код, следуя структуре, контрактам и правилам Svelte 5 Runes.
4. Напиши тесты, проверяющие критерии приёмки.
5. Запусти `npm run gate` в терминале и убедись, что всё зелено.
6. Сделай коммит(ы) по конвенции.
7. Проверь Definition of Done (раздел 12).

## Коммиты

- Используй Conventional Commits: `type(scope): <краткое описание>`, `fix(scope): <краткое описание>`, `test(scope): <краткое описание>`, `refactor(scope): <краткое описание>`, `chore(scope): <краткое описание>`.
- Коммить по ходу работы, небольшими логическими шагами.
- Все сообщения на русском языке, строчная буква, без точки в конце.
- Длина заголовка коммита не должна превышать 72 символов.

## Примеры

- `feat(upload): добавлена форма загрузки файла с метаданными и валидацией`
- `feat(db): добавлена поддержка meaning, composers и artists в схему`
- `test(sync): добавлен тест на идемпотентность для эндпоинта синхронизации`
- `test(filter): добавлены тесты фильтрации по вокалоидам и языкам`
- `fix(ui): корректная подсветка при событии timeupdate`
- `docs(readme): добавлено демо главной активности`

## Если что-то неясно

Обратись к `TECH.md`, раздел CONTRACT GAP. Если проблема не решается – остановись и запроси уточнение у пользователя.
