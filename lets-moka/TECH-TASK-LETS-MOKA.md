# TECH-TASK — Let's Moka!

Версия: v1 (18 августа 2026)

## 0. Назначение

`Let's Moka!` (`lets-moka`) — изолированное локальное web-приложение для системных аналитиков и тестировщиков. Оно объединяет медиафайл MP3/MP4/OGG, ASS-файл и значения формы в один эталонный JSON-мок, совместимый с контрактом данных `lets-uta`.

Приложение входит в репозиторий `lets-uta` только для удобства разработки и запуска. Оно не импортирует код, SQLite, SvelteKit или server-модули основного приложения. В будущем каталог `lets-moka` можно перенести в отдельный репозиторий без изменения его публичного поведения.

## 1. Источники истины

- `../TECH-TASK.md`, раздел `4. Контракт данных` — форма и ограничения JSON-мока.
- `../media/fixtures/MASA-WORKS-DESIGN/MASA WORKS DESIGN ft.LosstimeLife-ドンドルマ.json` — эталон сериализации.
- `../scripts/data/songs_dataset.json` — детерминированная тестовая фикстура.
- `../utils/ass_to_json.py` — исходная семантика разбора ASS.
- `../utils/duration_ms.py` — исходная семантика получения длительности через `ffprobe`.

Если это ТЗ не описывает правило, необходимое для выполнения критерия приёмки, используется `CONTRACT GAP`, а не молчаливое расширение контракта.

## 2. Ограничения и стек

- Go `1.25+` и стандартная библиотека Go.
- Локальный HTTP-сервер на `net/http`.
- HTML, CSS и небольшой vanilla JavaScript без CDN, frontend-фреймворков и внешнего runtime backend.
- `ffprobe` из системного FFmpeg — единственный источник длительности и media metadata.
- Один самостоятельный бинарник, в который UI-ассеты встраиваются через `embed`.
- Все операции выполняются локально; файлы не отправляются во внешние сервисы.
- Длинные операции ограничиваются контекстом и не приводят к зависанию HTTP-соединения.
- Тесты запускаются командами `gofmt -l .`, `go vet ./...` и `go test ./...`.

## 3. Пользовательский сценарий

1. Пользователь открывает локальную страницу `Let's Moka!`.
2. Выбирает медиафайл MP3, MP4 или OGG.
3. Приложение извлекает через `ffprobe` длительность и доступные теги.
4. Пользователь выбирает ASS-файл; приложение извлекает строки и тайминги.
5. Поля формы заполняются метаданными, но каждое значение остаётся редактируемым.
6. Пользователь проверяет и исправляет значения, после чего нажимает `Собрать JSON-мок`.
7. Приложение показывает отформатированный JSON с сохранёнными переносами строк.
8. Пользователь копирует JSON или скачивает его с именем `<название-мока>.json`.

Ошибки показываются на русском языке, рядом с соответствующим полем или в общем блоке ошибки. Технические пути, команды, stack trace и внутренние идентификаторы пользователю не показываются.

## 4. Контракт входных данных

### 4.1. Медиафайл

Поддерживаются только расширения `.mp3`, `.mp4`, `.ogg` без учёта регистра. Расширение проверяется и по имени файла, и по фактическому результату `ffprobe`. Максимальный размер входного файла: `100 MiB`.

Медиафайл определяет:

- `mediaKind`: `audio` для MP3/OGG, `video` для MP4;
- `durationMs`: положительное целое количество миллисекунд;
- начальные значения title, artists, composers и meaning, если соответствующие теги существуют;
- исходное имя файла для последнего сегмента автоматически собранного `filePath`.

Пустой или отсутствующий тег не затирает значение, которое пользователь уже ввёл вручную.

### 4.2. Поддерживаемые media tags

Приложение читает tags из `format.tags` и tags потоков, отдавая приоритет `format.tags`. Имена aliases проверяются в следующем порядке:

| Поле формы  | Алиасы ffprobe                        |
| :---------- | :------------------------------------ |
| `title`     | `title`, `track`, `name`              |
| `artists`   | `artist`, `album_artist`, `performer` |
| `composers` | `composer`, `composer_name`, `writer` |
| `meaning`   | `comment`, `description`              |

Значение списка разбирается по `;`, `/` или `,`, после чего каждый элемент trim-ится, пустые элементы удаляются, а порядок сохраняется.

### 4.3. ASS-файл

Поддерживается ASS в UTF-8, включая UTF-8 BOM. Разбирается секция `[Events]` и строки `Dialogue:`. Используется стандартный порядок ASS-полей:

`Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text`.

После `Text` разрешены запятые; они не разделяют поле текста. `\\N` преобразуется в `\n`. Текстовые override tags ASS удаляются только если это необходимо для отображения обычного текста; исходные пользовательские переносы сохраняются.

Время `H:MM:SS.cc` преобразуется в миллисекунды: часы, минуты и секунды переводятся в миллисекунды, centiseconds умножаются на `10`. Каждая валидная Dialogue-строка создаёт одну строку primary lyric и один timing с `source = "import"`.

Строки с пустым временем, некорректным временем, `endTime <= startTime` или временем за пределами длительности медиа отклоняют импорт с понятной ошибкой. Пустой ASS отклоняется: primary lyric и timing set не могут быть пустыми.

## 5. Контракт формы

Все поля, отмеченные `*`, обязательны. Значение не должно автоматически исчезать после выбора файла или ошибки валидации.

| Поле                     | JSON-поле            | Правило                                                                                                                       |
| :----------------------- | :------------------- | :---------------------------------------------------------------------------------------------------------------------------- |
| Название мока*           | `title`              | Непустая строка; изначально имя медиа без расширения, затем редактируется.                                                    |
| Путь к медиафайлу*       | `filePath`           | Единое редактируемое поле, автоматически собранное из метаданных и имени файла.                                               |
| Тип медиа*               | `mediaKind`          | `audio` или `video`; начальное значение следует расширению, поле остаётся редактируемым через select.                         |
| Длительность*            | `durationMs`         | Положительное целое в миллисекундах, полученное через `ffprobe`; доступно для ручной коррекции только с явным подтверждением. |
| Исполнители*             | `artists`            | Большое поле со списком через запятую; минимум один непустой элемент.                                                         |
| Композиторы*             | `composers`          | Большое поле со списком через запятую; минимум один непустой элемент.                                                         |
| Смысл или описание       | `meaning`            | Удобная textarea. Может стать JSON `null` только через чекбокс `NULL`.                                                        |
| Основной текст · 日本語* | `lyrics[0].text`     | Большая textarea; минимум одна строка; переносы сохраняются.                                                                  |
| Язык перевода            | `lyrics[1].language` | Понятные пользователю варианты `Русский` и `English`; в JSON записываются `ru` и `en`.                                        |
| Перевод                  | `lyrics[1].text`     | Необязательная большая textarea; число строк должно совпадать с Japanese text.                                                |

В интерфейсе никогда не показываются `ja`, `ru`, `en` как пользовательские названия языков: используются `日本語`, `Русский`, `English`. Внутри JSON используются только контрактные коды.

`text` и `meaning` используют многострочные textarea с видимой подсказкой о переносах. При сериализации реальный перенос строки записывается как JSON escape `\n`; обратный разбор JSON восстанавливает тот же текст.

### 5.1. Поля NULL

По контракту `meaning` — единственное nullable-поле. Рядом с ним находится checkbox `NULL`.

- При включении визуальное значение textarea сохраняется.
- Фактическое значение при сборке становится `null`.
- Textarea становится недоступной для редактирования, но не очищается.
- При выключении checkbox прежнее значение снова становится активным и используется в JSON.
- Если пользователь ввёл пустое значение и не выбрал `NULL`, форма отклоняется как неполная.

## 6. Правило `filePath`

`filePath` — относительный slash-путь для JSON, а не путь к локальному временно загруженному файлу. Он автоматически собирается так:

```text
media/fixtures/<подкаталог>/<имя-медиа>.<mp3|mp4|ogg>
```

Подкаталог по умолчанию берётся из первого исполнителя, а при его отсутствии — из названия мока. В подкаталоге пробелы заменяются на `-`; имя медиа сохраняется без изменений, включая пробелы и Unicode. Пользователь может отредактировать всё поле целиком.

Валидный `filePath`:

- содержит минимум один `/`;
- использует только `/`, не `\\`;
- не начинается с `/`, буквы диска или URL-схемы;
- не содержит пустых, `.` или `..` сегментов;
- заканчивается только на `.mp3`, `.mp4` или `.ogg` без учёта регистра;
- не содержит NUL, управляющих символов и query/fragment suffix.

Таким образом, `media/fixtures/Artist/song.mp3` валиден, а `song.mp3`, `C:\\music\\song.mp3`, `/tmp/song.mp3`, `../song.mp3` и `media/song.wav` отклоняются.

## 7. Контракт выходного JSON

Результат всегда является JSON-массивом с одним объектом песни. Ключи и порядок сериализации:

```json
[
  {
    "title": "...",
    "filePath": "media/fixtures/Artist/song.mp3",
    "mediaKind": "audio",
    "durationMs": 123456,
    "meaning": null,
    "composers": ["..."],
    "artists": ["..."],
    "lyrics": [
      {
        "language": "ja",
        "isPrimary": true,
        "text": "строка 1\nстрока 2",
        "timings": [
          {
            "lineIndex": 0,
            "startTime": 1000,
            "endTime": 2000,
            "source": "import"
          }
        ]
      }
    ]
  }
]
```

`lyrics[0]` всегда primary `ja`. Перевод, если заполнены язык и текст, добавляется вторым объектом с `isPrimary: false` и `timings: []`. Отдельный timing set для перевода не создаётся.

JSON выводится в UTF-8 с `SetEscapeHTML(false)`, отступом в два пробела и сохранением Unicode. Имя download-файла строится из текущего `title`: недопустимые для имени файла символы заменяются на `-`, расширение всегда `.json`.

## 8. HTTP-контракт

Публичный локальный маршрут приложения — `/`.

| Метод  | Маршрут     | Назначение                                                        |
| :----- | :---------- | :---------------------------------------------------------------- |
| `GET`  | `/`         | Форма приложения и состояние по умолчанию.                        |
| `POST` | `/generate` | Multipart upload, валидация и генерация JSON.                     |
| `GET`  | `/healthz`  | Возвращает `200` и короткий JSON для локальной проверки процесса. |
| `GET`  | `/static/*` | Только встроенные UI-ассеты, включая favicon и logo.              |

`POST /generate` возвращает HTML-страницу результата при успехе и HTML формы с сохранёнными значениями при ошибке. Кнопки `Скопировать JSON` и `Скачать JSON` работают на клиенте после успешного результата; сервер не хранит загруженные файлы.

Ожидаемые ошибки: `400` для пользовательских данных, `413` для превышения размера, `415` для неподдерживаемого расширения, `422` для невозможного разбора ASS/ffprobe metadata и `500` только для непредвиденной внутренней ошибки. В UI все они оформляются единым friendly error block.

## 9. Безопасность и обработка ошибок

- Ограничивать multipart body до `100 MiB` плюс небольшой запас для текстовых полей.
- Не передавать пользовательские имена файлов в shell-строку; `exec.CommandContext` получает аргументы отдельными значениями.
- Проверять `ffprobe` timeout и ненулевой exit code.
- Не возвращать абсолютные пути, raw stderr и stack traces.
- Экранировать пользовательский текст при HTML-рендеринге.
- Не исполнять ASS-теги и не интерпретировать содержимое текстов как HTML.
- Отбрасывать дубликаты в comma-separated lists после trim только если это явно согласовано в UI; порядок неповторяющихся элементов сохранять.
- Не писать загруженное медиа или ASS на постоянный диск.
- Не принимать вторичный язык без текста и текст без выбранного вторичного языка.
- Отменять частично обработанный запрос без выдачи неполного JSON.

## 10. Дизайн интерфейса

Интерфейс наследует editorial cyber-pop язык `lets-uta`, но остаётся самостоятельным:

- тёплая paper-поверхность `#eee9df`, ink `#1f2024`, muted `#64636a`;
- cyan `#00E5FF` для primary action/focus;
- pink `#FF4081` для active/error accents;
- yellow `#FFD543` для предупреждений;
- Georgia или другой локальный выразительный display-шрифт для заголовков;
- моноширинные uppercase-labels для технических подсказок;
- асимметричная двухколоночная desktop-форма, одна колонка на узком экране;
- заметные заголовки секций и большие поля для длинного текста;
- logo и favicon берутся из `lets-moka/logo_lets_moka_v1.png` и `lets-moka/favicon.ico`;
- без CDN, glassmorphism, декоративных blobs и постоянного neon glow.

Обязательные состояния: initial, media selected, ASS selected, metadata partially missing, validation error, successful preview, copy success, reduced motion.

Минимальная ширина — `320px`. Все controls имеют label/accessible name, `focus-visible`, клавиатурный порядок и текстовый статус для screen reader. При `prefers-reduced-motion: reduce` отключаются перемещения и декоративные анимации.

## 12. Acceptance Criteria

### AC-01. Полный эталонный мок

По валидным MP3/MP4/OGG, ASS и обязательным полям приложение генерирует JSON-массив из одной песни с полями `title`, `filePath`, `mediaKind`, `durationMs`, `meaning`, `composers`, `artists`, `lyrics` в форме контракта `lets-uta`.

### AC-02. Автоматическое заполнение

После выбора медиафайла длительность, media kind, имя мока и доступные tags заполняются автоматически. Пустые tags оставляют соответствующие поля пустыми и не перезаписывают ручные значения.

### AC-03. ASS и shared timings

ASS корректно разбирает время, `\\N`, BOM, дополнительные запятые в тексте и создаёт timing set только для primary `ja`. Все `lineIndex` совпадают с порядком строк. Перевод получает `timings: []`.

### AC-04. Переносы и длинные поля

Пользователь может удобно редактировать длинные `text` и `meaning`. Введённые переносы сохраняются в выходном JSON как `\n`, Unicode и японский текст не портятся.

### AC-05. Безопасный filePath

Автосборка и ручное редактирование `filePath` поддерживают slash-пути с расширениями `.mp3`, `.mp4`, `.ogg`; пробелы заменяются только в автоматически собранном подкаталоге, имя медиа не меняется. Небезопасные и неподдерживаемые пути отклоняются.

### AC-06. User-friendly language

Форма показывает языки как `日本語`, `Русский`, `English`, а в JSON сохраняет `ja`, `ru`, `en`. Пользовательские labels, placeholders, errors и statuses написаны на русском языке, кроме этих согласованных названий языков.

### AC-07. Nullable meaning

Checkbox `NULL` у `meaning` временно отключает поле без очистки визуального значения и сериализует его как JSON `null`. Повторное выключение восстанавливает введённое значение.

### AC-08. Строгая валидация

Пустые обязательные поля, invalid enum, invalid integer, duration `<= 0`, неподдерживаемые расширения, пустой ASS, несовпадение числа строк перевода и primary, timing за пределами duration и неверный filePath дают понятную ошибку без генерации частичного результата.

### AC-09. Preview и download

Успешный результат отображается в readable preview, позволяет скопировать JSON и скачать UTF-8 файл `<title>.json` с двумя пробелами. Download использует актуальное отредактированное название.

### AC-10. Ошибки и приватность

Превышение лимита, отсутствие ffprobe, timeout, повреждённый файл и внутренний сбой обрабатываются без падения процесса. Ответ не раскрывает абсолютный путь, shell-команду или stack trace.

### AC-11. Адаптивность и доступность

Основной сценарий работает на desktop, tablet и ширине `320px`, доступен с клавиатуры, имеет видимый focus, не теряет значения после ошибки и уважает `prefers-reduced-motion`.

### AC-12. Изоляция

`go test ./...`, `go vet ./...` и запуск бинарника из `lets-moka` не требуют Node.js, SvelteKit, SQLite или импорта пакетов основного приложения.

## 13. Acceptance-driven tests

Тесты проверяют наблюдаемое поведение и намеренно ломают границы:

### Unit

- ASS с BOM и `Dialogue` с запятыми в поле Text сохраняет весь текст.
- ASS с `\\N` создаёт реальные переносы строк и правильные `lineIndex`.
- Некорректное время, `end <= start`, пустой Events и time за duration отклоняются.
- Время с centiseconds конвертируется точно в целые миллисекунды.
- ffprobe JSON с format tags заполняет title/artists/composers/meaning; отсутствующие tags не создают fake values.
- Невалидный duration, повреждённый ffprobe JSON, ненулевой exit code и timeout возвращают безопасную ошибку.
- `filePath` принимает `media/fixtures/A-B/song name.mp3` и отклоняет `song.mp3`, абсолютный путь, backslash, `..`, query suffix и `.wav`.
- Builder сериализует `meaning: null`, сохраняет Unicode и делает translation timings пустым.
- Builder отклоняет пустые обязательные поля, secondary language без текста, разное число строк и timing вне duration.
- Round-trip JSON сохраняет реальные `\n`, Unicode, arrays и null.

### HTTP integration

- Успешный multipart request возвращает preview с полным JSON.
- Отсутствующий media/ASS, слишком большой body и неподдерживаемый extension возвращают дружелюбную ошибку без partial JSON.
- Введённые значения сохраняются после ошибки.
- ffprobe failure не показывает stderr и не оставляет temporary files.
- `GET /healthz` не требует загрузки и отвечает только локальным health payload.

### Проверка в браузере

- Выбор файлов заполняет метаданные, а поля остаются доступными для редактирования.
- Переключение `NULL` сохраняет видимое значение, отключает и снова включает textarea и изменяет только сериализованное значение.
- Названия японского текста и перевода отображаются как `日本語`, `Русский`, `English`.
- Длинный текст с несколькими абзацами сохраняется в preview и скачанном файле.
- Уведомление о копировании объявляется ассистивной технологией, а имя скачиваемого файла следует отредактированному названию.
