## 1. Проект

Медиаплеер для вокалоид-песен с функцией караоке. Пользователь локально загружает аудио (MP3/OGG) или видео (MP4), прикладывает метаданные (композиторы, вокалоиды, смысл песни) и текст песни (основной и, опционально, дополнительный, например, на другом языке). Приложение синхронизирует текст с воспроизведением, подсвечивая текущую строку (без плавной заливки, просто выделение). Синхронизация выполняется автоматически с помощью локальной модели Whisper, после чего пользователь может вручную корректировать таймкоды строк.

Аутентификации нет, пользователь один, данные хранятся локально в SQLite.

Цель: MVP, который работает в браузере и проходит гейт проверок.

## 2. Стек

- SvelteKit 2 (fullstack, `adapter-node`), Svelte 5 (runes)
- TypeScript, strict
- better-sqlite3, файл базы `karaoke.db` в корне
- Тесты: vitest + Playwright (e2e)
- Проверки: prettier, eslint, svelte-check, knip
- Для синхронизации: `whisper-node` (локальный Whisper) – получение таймкодов слов
- Для разбиения текста на строки: `sentence-splitter` (русский/английский) + `kuromoji.js` (японский)
- Без ORM, без стейт-менеджеров, без UI-фреймворков. Стили — обычный CSS в компонентах.

| поле        | тип SQLite | ограничения                                           |
| :---------- | :--------- | :---------------------------------------------------- |
| `id`        | INTEGER    | PRIMARY KEY AUTOINCREMENT                             |

| `isPrimary` | INTEGER    | NOT NULL DEFAULT 1 (1 – основной, 0 – дополнительный) |
| `text`      | TEXT       | NOT NULL (весь текст, с переносами строк)             |
| `createdAt` | TEXT       | NOT NULL DEFAULT (datetime('now')), ISO-строка        |

### Таблица `timings`

| поле        | тип SQLite | ограничения                                         |
| :---------- | :--------- | :-------------------------------------------------- |
| `id`        | INTEGER    | PRIMARY KEY AUTOINCREMENT                           |
| `songId`    | INTEGER    | NOT NULL, FOREIGN KEY (songs.id) ON DELETE CASCADE  |
| `lyricId`   | INTEGER    | NOT NULL, FOREIGN KEY (lyrics.id) ON DELETE CASCADE |
| `lineIndex` | INTEGER    | NOT NULL (индекс строки в тексте, начиная с 0)      |

### Таблица `settings` (опционально)

| поле    | тип SQLite | ограничения |
| :------ | :--------- | :---------- |
| `key`   | TEXT       | PRIMARY KEY |

Начальные настройки: `theme=light`, `volume=0.8`.

```ts
export type Song = {
  id: number;
  title: string;
  filePath: string;
  duration: number; // секунды
  meaning?: string | null;
  composers: string[];
  artists: string[];
  createdAt: string; // ISO
};

export type SongDbRow = Omit<Song, 'artists' 'composers' |> & {
  composers: string; // JSON text в SQLite
  artists: string;   // JSON text в SQLite
};

export type Lyric = {
  id: number;
  songId: number;
  language: 'ru' | 'ja' | 'en';
  isPrimary: boolean;
  text: string; // весь текст, строки разделены \n
  createdAt: string;
};

export type Timing = {
  id: number;
  songId: number;
  lyricId: number;
  lineIndex: number;
  startTime: number; // мс
  endTime: number;   // мс
};

export type SongWithDetails = Song & {
  lyrics: Lyric[];
  timings: Timing[];
};

export type UploadInput = {
  file: File; // в FormData
  title: string;
  primaryLyric: string;
  primaryLanguage: 'ru' | 'ja' | 'en';
  secondaryLyric?: string;
  secondaryLanguage?: 'ru' | 'ja' | 'en';
  meaning?: string;
  composers: string[]; // передается через запятую в форме, парсится в массив
  artists: string[];   // передается через запятую в форме, парсится в массив
};
```

## 7. Маршруты

| путь               | что делает                                                                         | actions / методы                         |
| :----------------- | :--------------------------------------------------------------------------------- | :--------------------------------------- |
| `/`                | список песен (карточки с названием, авторами, артистами и длительностью) + фильтры | GET                                      |
| `/upload`          | форма загрузки медиа, метаданных (meaning, composers, artists) и текстов           | POST (загрузка)                          |
| `/songs/[id]`      | плеер + текст с подсветкой, отображение метаинформации, кнопка синхронизации       | GET, POST (обновление таймкодов вручную) |
| `/songs/[id]/sync` | (POST) запускает синхронизацию, возвращает статус                                  | POST (JSON)                              |
| `/settings`        | настройки темы, громкости, хоткеев                                                 | GET, POST                                |

Правила:

- Формы работают через `use:enhance` и обычные `<form method="POST">`.
- Загрузка файлов – через `enctype="multipart/form-data"`.
- Поля `composers` и `artists` в форме `/upload` принимают строки с разделителем-запятой.
- При успешной загрузке песни – редирект на `/songs/[id]`.
- При ошибке валидации – `fail(400)` с ошибкой и сохранёнными значениями.
- Несуществующий id – `error(404)`.

## 8. Валидация

`src/lib/karaoke/validate.ts`:

```ts
validateUploadInput(data: {
  title: unknown;
  file: File | undefined;
  primaryLyric: unknown;
  primaryLanguage: unknown;
  secondaryLyric?: unknown;
  secondaryLanguage?: unknown;
  meaning?: unknown;
  composers?: unknown;
  artists?: unknown;
}): 
  | { ok: true; value: UploadInput }
  | { ok: false; error: string }
```

Правила:

- `title` – обрезается, не пустой, от 1 до 200 символов.
- `file` – обязателен, размер < 100 МБ (проверка на стороне клиента и сервера), расширение `.mp3`, `.ogg`, `.mp4`.
- `primaryLyric` – обрезается, не пустой, до 8191 символов.
- `primaryLanguage` – строго одно из `'ru'`, `'ja'`, `'en'`.
- `secondaryLyric` – если есть, до 8191 символов, не пустой после обрезки.
- `secondaryLanguage` – если передан `secondaryLyric`, обязательно указание языка строго из `'ru'`, `'ja'`, `'en'`, не совпадающего с `primaryLanguage`.
- `meaning` – опционально, до 4000 символов.
- `composers` – строка через запятую или массив; элементы обрезаются от пробелов, пустые исключаются. Каждый элемент до 100 символов.
- `artists` – строка через запятую или массив; элементы обрезаются от пробелов, пустые исключаются. Каждый элемент до 100 символов.
- Ошибки на русском: `Название обязательно`, `Название длиннее 200 символов`, `Файл обязателен`, `Файл слишком большой (макс. 100 МБ)`, `Неверный формат файла`, `Основной текст обязателен`, `Текст длиннее 8191 символов`, `Неверно указан язык`, `Второй язык не может совпадать с основным`, `Описание слишком длинное (макс. 4000 символов)`.

## 9. Тесты

Тесты выводятся из критериев приёмки слайса, не из реализации. На каждый слайс минимум:

- тест на каждый критерий приёмки;
- тест на путь ошибки (невалидный ввод, отсутствующий id);
- тесты чистой логики (`validate`, `splitter`) без базы.

База в тестах – `:memory:` через `getDb(':memory:')`. Файл `karaoke.db` не трогаем.

Actions роутов тестируются вызовом экспортированной функции напрямую с подставленным `request` и `FormData` (для загрузки) или JSON.

Для синхронизации – мокаем `whisper-node`, возвращаем заранее подготовленные таймкоды.

Property-based тесты (fast-check) для `splitter` – проверяем инварианты (например, склеивание строк даёт исходный текст, количество строк не превышает количество слов и т.д.).

3. `npm run seed` наполняет базу треками из `songs_dataset.json`, поля `composers` и `artists` корректно десериализуются в массивы, `meaning` сохраняется; повторный запуск не дублирует записи.

*Примечание:* Файл `scripts/data/songs_dataset.json` используется в двух контурах:

- Сид базы данных (`scripts/seed.ts`): скрипт парсит `songs_dataset.json`, сохраняет треки в `songs`, тексты в `lyrics` и таймкоды в `timings`, обеспечивая наполнение рабочей БД при локальной разработке (`npm run seed`).
- Фикстуры для тестов (`tests/integration/` и `tests/e2e/`): импортируется напрямую для проверки маппинга данных, фильтрации и воспроизведения с таймкодами без ручного создания моков.

### Слайс 3 — синхронизация (Whisper)

**Файлы:** `src/routes/songs/[id]/+page.svelte` (добавить кнопку «Синхронизировать»), `src/routes/songs/[id]/sync/+server.ts`, `src/lib/server/sync.ts`, `src/lib/karaoke/synchronizer.ts` (обёртка над whisper).

**Что делает:** На странице песни – кнопка «Синхронизировать». При нажатии отправляет POST на `/songs/[id]/sync`. На сервере запускается процесс: извлекается аудио из файла (если видео), передаётся в Whisper для получения транскрипции с таймкодами слов. Затем агрегируются таймкоды для каждой строки основного текста (по словам). Сохраняются в таблицу `timings`. По окончании возвращает статус, страница обновляется (или показывается прогресс).

**Критерии приёмки:**

1. После успешной синхронизации у песни появляются таймкоды для всех строк основного текста.
2. При повторной синхронизации старые таймкоды удаляются и заменяются новыми (идемпотентность).
3. Если Whisper не смог распознать (ошибка) – возвращается ошибка, существующие таймкоды не повреждаются.
4. Во время синхронизации интерфейс не блокируется (показывается индикатор загрузки/прогресс).
5. Если нет основного текста – синхронизация невозможна (ошибка).

**Тесты:** интеграционный тест с моком Whisper (возвращает фиктивные таймкоды из фикстур), проверка сохранения в таблицу `timings`. Тест на идемпотентность – два последовательных вызова не дублируют записи.

### Слайс 4 — ручная корректировка таймкодов

**Файлы:** `src/lib/ui/TimelineEditor.svelte`, обновить `src/routes/songs/[id]/+page.svelte` (добавить редактор в режиме редактирования), `src/routes/songs/[id]/+page.server.ts` (обработка POST для обновления таймкодов).

**Что делает:** На странице песни – переключатель «Редактировать таймкоды». В режиме редактирования отображается `TimelineEditor`: список строк с полями ввода start/end (в мс или секундах), можно изменять значения вручную. После сохранения – обновляются таймкоды в БД.

**Критерии приёмки:**

1. Можно изменить start/end для любой строки, изменения сохраняются в БД.
2. Валидация: `startTime >= 0`, `endTime > startTime`, `endTime <= duration * 1000`.
3. При ошибке валидации – форма не отправляется, показывается ошибка под проблемной строкой.
4. После сохранения страница переключается в режим просмотра и отображает новые таймкоды в плеере.

**Тесты:** unit-тест для валидации интервалов таймкодов; интеграционный тест для POST-обновления `timings`.

### Слайс 5 — второй текст

**Файлы:** `src/routes/upload/+page.svelte` (уже есть), `src/routes/songs/[id]/+page.svelte` (переключение между текстами).

**Что делает:** При загрузке можно добавить второй текст. На странице песни – переключатель (вкладки или выпадающий список) для выбора языка текста. При переключении – отображается соответствующий текст и его таймкоды (если они есть). Синхронизация применяется только к основному тексту (первичному). Для дополнительного текста синхронизация не выполняется.

**Критерии приёмки:**

1. При загрузке с двумя текстами – оба сохраняются с флагами `isPrimary = 1` и `isPrimary = 0`.
2. На странице песни можно переключиться между текстами, отображается соответствующий контент.
3. Таймкоды отображаются только для того текста, для которого они созданы (для основного – подсвечиваются, для дополнительного без таймкодов – отображаются простым текстом).
4. При переключении – подсветка работает, если есть таймкоды для выбранного текста.

**Тесты:** проверка рендеринга обоих текстов и изоляции таймкодов по `lyricId`.
