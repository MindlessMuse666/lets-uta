## 1. Проект

Медиаплеер для вокалоид-песен с функцией караоке. Пользователь локально загружает аудио (MP3/OGG) или видео (MP4), прикладывает текст песни (основной и, опционально, дополнительный, например, на другом языке). Приложение синхронизирует текст с воспроизведением, подсвечивая текущую строку (без плавной заливки, просто выделение). Синхронизация выполняется автоматически с помощью локальной модели Whisper, после чего пользователь может вручную корректировать таймкоды строк.

Аутентификации нет, пользователь один, данные хранятся локально в SQLite.

Цель: MVP, который работает в браузере и проходит гейт проверок.

## 2. Стек

- SvelteKit 2 (fullstack, `adapter-node`), Svelte 5 (runes)
- TypeScript, strict
- better-sqlite3, файл базы `karaoke.db` в корне
- Тесты: vitest + Playwright (e2e)
- Проверки: prettier, eslint, svelte-check, knip
- Для синхронизации: `whisper-node` (локальный Whisper) – получение таймкодов слов
- Для разбиения текста на строки: `sentence-splitter` (русский/английский) + `kuromoji.js` (японский)
- Без ORM, без стейт-менеджеров, без UI-фреймворков. Стили — обычный CSS в компонентах.

## 4. Контракт данных

### Таблица `songs`

| поле        | тип SQLite | ограничения                                    |
| ----------- | ---------- | ---------------------------------------------- |
| `id`        | INTEGER    | PRIMARY KEY AUTOINCREMENT                      |
| `title`     | TEXT       | NOT NULL                                       |
| `filePath`  | TEXT       | NOT NULL (путь к загруженному файлу)           |
| `duration`  | INTEGER    | NOT NULL (длительность в секундах)             |
| `createdAt` | TEXT       | NOT NULL DEFAULT (datetime('now')), ISO-строка |

### Таблица `lyrics`

| поле        | тип SQLite | ограничения                                           |
| ----------- | ---------- | ----------------------------------------------------- |
| `id`        | INTEGER    | PRIMARY KEY AUTOINCREMENT                             |
| `songId`    | INTEGER    | NOT NULL, FOREIGN KEY (songs.id) ON DELETE CASCADE    |
| `language`  | TEXT       | NOT NULL (например, 'ru', 'ja', 'en')                 |
| `isPrimary` | INTEGER    | NOT NULL DEFAULT 1 (1 – основной, 0 – дополнительный) |
| `text`      | TEXT       | NOT NULL (весь текст, с переносами строк)             |
| `createdAt` | TEXT       | NOT NULL DEFAULT (datetime('now')), ISO-строка        |

### Таблица `timings`

| поле        | тип SQLite | ограничения                                         |
| ----------- | ---------- | --------------------------------------------------- |
| `id`        | INTEGER    | PRIMARY KEY AUTOINCREMENT                           |
| `songId`    | INTEGER    | NOT NULL, FOREIGN KEY (songs.id) ON DELETE CASCADE  |
| `lyricId`   | INTEGER    | NOT NULL, FOREIGN KEY (lyrics.id) ON DELETE CASCADE |
| `lineIndex` | INTEGER    | NOT NULL (индекс строки в тексте, начиная с 0)      |
| `startTime` | INTEGER    | NOT NULL (время начала строки в мс)                 |
| `endTime`   | INTEGER    | NOT NULL (время окончания строки в мс)              |

Индексы: `(songId, lyricId, lineIndex)` уникальный.

### Таблица `settings` (опционально)

| поле    | тип SQLite | ограничения |
| ------- | ---------- | ----------- |
| `key`   | TEXT       | PRIMARY KEY |
| `value` | TEXT       | NOT NULL    |

Начальные настройки: `theme=light`, `volume=0.8`.

### Типы приложения (`src/lib/karaoke/types.ts`)

```ts
export type Song = {
  id: number;
  title: string;
  filePath: string;
  duration: number; // секунды
  createdAt: string; // ISO
};

export type Lyric = {
  id: number;
  songId: number;
  language: string; // 'ru' | 'ja' | 'en'
  isPrimary: boolean;
  text: string; // весь текст, строки разделены \n
  createdAt: string;
};

export type Timing = {
  id: number;
  songId: number;
  lyricId: number;
  lineIndex: number;
  startTime: number; // мс
  endTime: number;   // мс
};

export type SongWithDetails = Song & {
  lyrics: Lyric[];
  timings: Timing[];
};

export type UploadInput = {
  file: File; // в FormData
  title: string;
  primaryLyric: string;
  secondaryLyric?: string;
  primaryLanguage: string;
  secondaryLanguage?: string;
};
```

Поля `createdAt` – ISO-строки.

| путь               | что делает                                          | actions / методы                         |

## 8. Валидация

`src/lib/karaoke/validate.ts`:

```ts
validateUploadInput(data: {
  title: unknown;
  file: File | undefined;
  primaryLyric: unknown;
  primaryLanguage: unknown;
  secondaryLyric?: unknown;
  secondaryLanguage?: unknown;
}): 
  | { ok: true; value: UploadInput }
  | { ok: false; error: string }
```

Правила:

- `title` – обрезается, не пустой, до 200 символов.
- `file` – обязателен, размер < 100 МБ (проверка на стороне клиента и сервера), расширение `.mp3`, `.ogg`, `.mp4`.
- `primaryLyric` – обрезается, не пустой, до 8191 символов.
- `primaryLanguage` – одно из `'ru'`, `'ja'`, `'en'`.
- `secondaryLyric` – если есть, до 8191 символов, не пустой после обрезки.
- `secondaryLanguage` – если есть, одно из `'ru'`, `'ja'`, `'en'`, не совпадает с `primaryLanguage`.
- Ошибки на русском: `Название обязательно`, `Название длиннее 200 символов`, `Файл обязателен`, `Файл слишком большой (макс. 100 МБ)`, `Неверный формат файла`, `Основной текст обязателен`, `Текст длиннее 8191 символов`, и т.д.

`src/lib/karaoke/splitter.ts` – чистая функция для разбиения текста на строки (использует библиотеки). На вход принимает текст и язык, возвращает массив строк. Если текст уже содержит переносы строк, сохраняет их как есть.

## 9. Тесты

Тесты выводятся из критериев приёмки слайса, не из реализации. На каждый слайс минимум:

- тест на каждый критерий приёмки;
- тест на путь ошибки (невалидный ввод, отсутствующий id);
- тесты чистой логики (`validate`, `splitter`) без базы.

База в тестах – `:memory:` через `getDb(':memory:')`. Файл `karaoke.db` не трогаем.

Actions роутов тестируются вызовом экспортированной функции напрямую с подставленным `request` и `FormData` (для загрузки) или JSON.

Для синхронизации – мокаем `whisper-node`, возвращаем заранее подготовленные таймкоды.

Property-based тесты (fast-check) для `splitter` – проверяем инварианты (например, склеивание строк даёт исходный текст, количество строк не превышает количество слов и т.д.).

### Слайс 2 — список песен и плеер

**Файлы:** `src/routes/+page.server.ts`, `src/routes/+page.svelte`, `src/routes/songs/[id]/+page.server.ts`, `src/routes/songs/[id]/+page.svelte`, компонент `Player.svelte`.

**Что делает:** Главная страница – список песен (карточки с названием и длительностью). При клике – переход на `/songs/[id]`. Страница песни – плеер (HTML5 audio/video), отображение основного текста строками. При воспроизведении текущая строка подсвечивается на основе таймкодов (если есть). Если таймкодов нет – текст отображается без подсветки.

**Критерии приёмки:**

1. Список песен загружается, отсортирован по дате добавления (новые сверху).
2. Плеер воспроизводит загруженный файл.
3. Текст отображается по строкам (разбивка через `splitter`).
4. При наличии таймкодов – текущая строка подсвечивается (цвет #FF4081, фон лёгкий).
5. Перемотка обновляет подсветку.
6. Пустой список показывает `EmptyState`.

**Тесты:** e2e-тест с загруженной песней и таймкодами (заглушка) – проверка подсветки при воспроизведении.

### Слайс 3 — синхронизация (Whisper)

**Файлы:** `src/routes/songs/[id]/+page.svelte` (добавить кнопку «Синхронизировать»), `src/routes/songs/[id]/sync/+server.ts`, `src/lib/server/sync.ts`, `src/lib/karaoke/synchronizer.ts` (обёртка над whisper).

**Что делает:** На странице песни – кнопка «Синхронизировать». При нажатии отправляет POST на `/songs/[id]/sync`. На сервере запускается процесс: извлекается аудио из файла (если видео), передаётся в Whisper для получения транскрипции с таймкодами слов. Затем агрегируются таймкоды для каждой строки основного текста (по словам). Сохраняются в таблицу `timings`. По окончании возвращает статус, страница обновляется (или показывается прогресс).

**Критерии приёмки:**

1. После успешной синхронизации у песни появляются таймкоды для всех строк основного текста.
2. При повторной синхронизации старые таймкоды удаляются и заменяются новыми (идемпотентность).
3. Если Whisper не смог распознать (ошибка) – возвращается ошибка, таймкоды не меняются.
4. Во время синхронизации интерфейс не блокируется (показывается индикатор загрузки).
5. Если нет основного текста – синхронизация невозможна (ошибка).

**Тесты:** интеграционный тест с моком Whisper (возвращает фиктивные таймкоды), проверка сохранения. Тест на идемпотентность – два вызова не дублируют записи.

### Слайс 4 — ручная корректировка таймкодов

**Файлы:** `src/lib/ui/TimelineEditor.svelte`, обновить `src/routes/songs/[id]/+page.svelte` (добавить редактор в режиме редактирования), `src/routes/songs/[id]/+page.server.ts` (обработка POST для обновления таймкодов).

**Что делает:** На странице песни – переключатель «Редактировать таймкоды». В режиме редактирования отображается `TimelineEditor`: список строк с полями ввода start/end (в мс или секундах), можно изменять значения вручную. После сохранения – обновляются таймкоды в БД.

**Критерии приёмки:**

1. Можно изменить start/end для любой строки, изменения сохраняются.
2. Валидация: start >= 0, end > start, end <= длительность песни.
3. При ошибке валидации – форма не отправляется, показывается ошибка.
4. После сохранения страница обновляется и показывает новые таймкоды в плеере.

**Тесты:** unit-тест для валидации таймкодов; интеграционный тест для обновления.

### Слайс 5 — второй текст

**Файлы:** `src/routes/upload/+page.svelte` (уже есть), `src/routes/songs/[id]/+page.svelte` (переключение между текстами).

**Что делает:** При загрузке можно добавить второй текст. На странице песни – переключатель (вкладки или выпадающий список) для выбора языка текста. При переключении – отображается соответствующий текст и его таймкоды (если они есть). Синхронизация применяется только к основному тексту (первичному). Для дополнительного текста синхронизация не выполняется (или можно выполнить отдельно, но в MVP – только для основного).

**Критерии приёмки:**

1. При загрузке с двумя текстами – оба сохраняются.
2. На странице песни можно переключиться между текстами, отображается соответствующий текст.
3. Таймкоды отображаются только для того текста, для которого они есть (если есть для основного – показываются, для дополнительного – нет).
4. При переключении – подсветка работает, если есть таймкоды для выбранного текста.

**Тесты:** проверка отображения обоих текстов.
